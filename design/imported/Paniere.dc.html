Design proposal · 01

PANIERE — a basket ledger, not a health dashboard

The brief's hardest requirement is a tone problem, not a data problem. So the whole product is framed as a printed statistical bulletin — flush-left, ruled, tabular, unglamorous. Nobody reads a bulletin as advice. That framing does most of the work the disclaimer would otherwise have to do alone.

Rule 01
Red talks about the data.
Never about the food.

Modernist's single accent is reserved for structure, navigation and the data-quality domain — quarantine, review, corrections. It never touches a nutrient value or a bar. That kills the traffic-light read at the root instead of captioning around it.

Rule 02
Uncertainty is texture,
never colour.

Thin data is drawn as hatching on an ink bar. Colourblind-safe by construction, and always paired with a word and a figure.

Rule 03
Draft is a shape,
not a colour.

The three trust states differ by fill — hatched, half, solid — plus an icon and a word. All three sit in ink. Draft therefore reads as "early", never as "broken". It is the normal state and it looks like one.

Rule 04
Receipt text is evidence.
It gets a box.

Every raw OCR string — 40G DLL PATE NOI — is set in monospace inside a hairline box. Boxed = printed on paper. Unboxed = written by the app. Hostile strings become a legible type class.

Assumptions I made
  1. Fonts. Archivo is the design system's voice, and "no CDN" is a hard constraint. Both hold if the Python build inlines a Latin+digits Archivo subset as a base64 @font-face (≈32 KB). Declared fallback is system-ui — the layout is metric-tolerant.
  2. Data-shaped copy stays in the data. disclaimer, status_reasons and quarantine reasons are Italian in the file, so the switcher localises interface strings only and renders those fields verbatim. Localising them is the generator's job, not the UI's.
  3. The 33-vs-8 gap is shown, not smoothed. The brief says 33 never read; the file lists 8. Data quality reconciles 131 → 127 → 88 and labels the remaining 25 receipts unaccounted rather than picking a number.
  4. Sample size. items[] carries 41 example lines; filter counts come from coverage.by_state (all 2 275) and the list says so.
Palette & contrast

Modernist's mono-red replaces the blue/orange pair. Measured against each ground:

3.8:1 is used for chrome and 17 px+ only. Body-size red always uses the deep step. Nothing in the product relies on hue to carry meaning.

Reading the nutrient row

Four facts, one row, no judgement anywhere. The axis runs 0 → 200% of the EU reference so the reference marker always sits dead centre: the eye learns one landmark and reads every row against it.

  1. Value + unit, tabular, right-aligned into a column.
  2. Ink bar = the figure. Solid at ≥80% coverage, hatched below it — same length, different confidence.
  3. Centre rule = the EU reference, labelled RI. A landmark, not a target.
  4. Whisker = the bracket if estimated quantities are re-included. Protein 62 → 133 g is a real 114% swing, and the row shows it.
  5. Chips = coverage, largest single line, and a red flag only when one product supplies ≥25%.

Cholesterol has no EU reference, so it gets no track at all — an empty rail beside "212.5 mg" would read as zero. It shows the number and says why there is nothing to compare it to.

06 · The core problem

Low confidence is not bad news. It is the finding.

A dashboard feels worthless when its numbers are hedged, because the numbers were the product. So the product is not the numbers. It is the reconstruction — 131 photographs of thermal paper turned into 2 275 lines, 356 of which can carry a nutrient. Coverage stops being an apology and becomes the thing you came to read.

01
Coverage is the headline

15.6% is set at 54 px on the first screen, captioned as a fact about the data. There is no household score to compete with it, so nothing has to be hedged later.

02
Doubt gets a width

Protein is 62 g printed, 133 g with estimates. The whisker under the bar draws that distance. A number with a measured width reads as rigour; a number with a warning icon reads as failure.

03
Texture, not colour

Hatching says "thin" without saying "wrong". No token for green or amber exists, so the semaphore the brief forbids is not available to build.

04
Gaps are addressable

Every hole is a row you can act on: 51 quarantined lines with reasons, €578 of untallied mince, 25 unaccounted receipts. Data quality is a place to work, not a disclaimer to scroll past.

05
The user can move it

Scanning a receipt shows coverage go 15.6 → 15.7%. Small, real, and yours. A product you can improve by hand is never worthless — even at 15.6%.

Test for the win condition in the brief: a stranger opens Nutrients and sees a bar next to 3X200G THON NATURE, a coverage figure on every row, and a title that says bought. The register is a shopping ledger before a single word of explanation is read — and the numbers are still there to read.
